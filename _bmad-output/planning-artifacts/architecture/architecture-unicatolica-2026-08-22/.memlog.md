- (constraint) Prazo crítico: entrega funcional (aplicação no ar) até a próxima semana (~2026-08-29). Time é o grupo de alunos do PACEXT, não um time profissional formado.
- (decision) [ADOPTED] Stack já validada com o orientador (docs/unicatolica-pacext-contexto.md §5-6): Frontend Angular/TS; Backend Java + Quarkus + Hibernate ORM (JAX-RS Resource+Service por módulo); PostgreSQL; JWT; monólito multimodular (não microsserviços); TDD+SOLID; DDD focado no núcleo (interação de comunidade). Não é uma decisão em aberto para este spine — só formalizar como AD e fechar as lacunas que o relatório não cobre (contratos entre módulos, storage de arquivos, deploy, particionamento por pessoa).
- (version) Angular: latest stable ^22 (jun/2026), CLI padrão. Backend: Java 21 LTS + Quarkus 3.33 LTS (mar/2026, suporte até mar/2027) + Hibernate ORM. PostgreSQL (versão a definir pelo provedor de hosting). Verificado via web em 2026-08-22.
- (constraint) Hosting: Render escolhido pelo time para a aplicação (web services). RISCO verificado na web: Postgres gratuito do Render expira em 30 dias + 14 dias de carência antes de apagar os dados — inaceitável para um projeto com potencial de virar produto real. Alternativa verificada: Neon Postgres free tier é persistente, sem expiração (0.5GB/projeto, 100 CU-hora/mês, autoscale até 2 CU). Recomendação: Render para os serviços web (frontend Angular + backend Quarkus), Neon para o Postgres gerenciado.
- (decision) Escopo must-have da semana 1: RF01-RF13 (Identidade/Acesso) + RF21-RF31 (Comunidades) + RF32-RF36 (Publicações) ponta a ponta, deployado. RF14-RF20 (Perfil) e RF37-RF42 (Discussões/comentários em árvore) são stretch goal se sobrar tempo — não bloqueiam a entrega funcional.
- (decision) Divisão do time: horizontal por camada — Frontend (Angular) x Backend (Quarkus/Postgres). A costura crítica entre os dois lados é o contrato REST/OpenAPI (já exigido por RNF08), que precisa estar fechado antes de cada lado avançar isoladamente.
- (decision) Hosting: Render para os web services (frontend Angular estático + backend Quarkus via Docker); Neon para o Postgres gerenciado (free tier persistente, sem expiração) em vez do Postgres gratuito do Render (expira em 30 dias).
- (decision) Migrations: Liquibase (extensão nativa Quarkus), changelogs versionados no repo — nunca alterar schema manualmente em produção.
- (decision) Code review: CI verde é suficiente pra mergear em main, sem exigência de aprovação humana — decisão do time dado o prazo e tamanho do grupo.
- (decision) OpenAPI-first: contrato openapi.yaml na raiz do repo é a fonte de verdade acordada entre frontend e backend antes de qualquer lado implementar um endpoint novo — não é opcional dado RNF08 (interoperabilidade de API) e a divisão horizontal (frontend e backend avançam em paralelo, sem se ver).
- (decision) Envelope de erro padrão para toda a API: {error:{code,message,details}} + status HTTP semanticamente correto. Um único formato para os 12 módulos, evita 4 pessoas inventando 4 formatos de erro diferentes.
- (decision) Limites de módulo dentro do monólito: cada módulo é dono das próprias tabelas (mapa componente→requisitos já definido no C4 nível 3). Leitura entre módulos via associação JPA direta é permitida (schema único compartilhado, mais simples pro prazo de 1 semana); escrita em tabela de outro módulo só através do service do módulo dono, nunca acesso direto a repositório/tabela alheios — preserva a possibilidade de separar em serviços mais tarde sem reescrever tudo.
- (decision) Frontend: Angular publicado como Render Static Site (build de produção, CDN gratuito). Backend: Quarkus como Render Web Service via Docker. CORS: backend permite explicitamente a origem do Static Site; JWT transportado via header Authorization Bearer, nunca cookie — sem superfície CSRF, consistente com o C4 nível 2 já definido no contexto (spa -> api via header Authorization).
- (decision) [ADOPTED] Filtro de segurança JWT (C4 nível 3 do contexto): intercepta toda requisição autenticada, valida o token e aplica controle de acesso por perfil (RF08/RF09/RF13) antes de encaminhar aos 12 componentes de módulo.
